Tool choices & why

  • xUnit + Moq: already the SE3022 stack; Moq supports strict mocks, ref/out stubs and callbacks.
  • Stryker.NET: the de-facto .NET mutation tool; HTML report shows each mutant in the source.
  • k6: scripts are code (versioned, reviewable), thresholds act as SLO gates, and it runs headless in CI.
  • Roslyn analyzers + custom gate: SonarQube-style metrics without a server or secret token.

Automation design decisions

  • One script, two runners: CI calls run-pipeline.sh, so local demo = CI behaviour.
  • Stages run in parallel where independent; quality reuses the unit-test coverage artifact.
  • Disposable load stack on tmpfs MySQL; the Kafka publisher is disabled (outbox still written).
  • Gate philosophy: hard limits for security/coverage, a ratchet for legacy smells (clean as you code).
